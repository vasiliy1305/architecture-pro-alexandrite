Задание 1. Анализ, идентификация проблем и решений, планирование

1. проблемные места
- отсутствие наблюдаемости - нет мониторинга, логирования и трейсинга. Невозможно понять, где теряются заказы
- низкая производительность MES UI - медленная загрузка списка заказов даже с пагинацией
- долгий расчет стоимости заказа (до 30 мин) в MES API, при этом расчет синхронный и блокирующий
- отсутствие отказоустойчивости - каждый сервис и бд представлены в единственном экземпляре
- ненадежная интеграция через rabbit сообщения могут теряться 
- рост нагрузки без масштабирования - с открытием API и выходом на новые рынки RPS вырос но инфраструктура осталась прежней
- нет механизмов кэширования - все читается напрямую из бд включая часто запрашиваемый список заказов


2. Инициативы
- внедрить наблюдаемость мониторинг (Prometheus/Grafana), логирование (ELK) и трейсинг (OpenTelemetry + Jaeger)
- оптимизировать загрузку списка заказов в MES через кэширование (серверное, паттерн Cache-Aside + Redis)
 - сделать расчет стоимости заказа асинхронным с уведомлением по очереди
- настроить отказоустойчивость Rabbit dead-letter exchange, retry, мониторинг очередей
- добавить горизонтальное масштабирование сервисов и репликацию бд
- внедрить паттерн Circuit Breaker для защиты от каскадных сбоев при вызове внешних API
- настроить CI/CD с автоматическим тестированием и откатом, чтобы ускорить релизы



3. инициативы в порядке приоритета и стратегия
Целевая архитектура через 6 месяцев:

- все ключевые сервисы покрыты мониторингом, логами и трейсингом
- MES UI работает быстро благодаря кэшированию
- расчет стоимости асинхронный, без блокировки.
- система устойчива к пиковым нагрузкам и отказам внешних сервисов
- заказы не теряются, статусы синхронизируются надежно через Rabbit


4. топ 3 инициативы на ближайшие 6 месяцев

- внедрение наблюдаемости, без нее невозможно диагностировать проблемы и оценивать эффективность других изменений
- кэширование списка заказов в MES , быстро решает боль операторов и улучшает UX
- асинхронизация расчета стоимости,  устраняет главный источник тайм аутов и улучшает стабильность API

эти три инициативы дают максимальный эффект при умеренных затратах и ложатся в основу дальнейших улучшений.
