Задание 4. Логирование

1. какие логи нужно собирать
Системы для первоочередного логирования:
- MES API (C#) ключевой сервис расчета стоимости, часто зависает
- CRM API (Spring Boot) отвечает за переход заказа в производство
- Shop API (Spring Boot) точка входа для всех заказов
- RabbitMQ интеграционная шина, где теряются сообщения
Примеры логов уровня INFO:

Заказ {order_id} создан пользователем {user_id}
Файл 3D-модели загружен для заказа {order_id}
Статус заказа изменен с {old_status} на {new_status} в {system}
Сообщение отправлено в очередь {queue_name}, order_id={order_id}
Сообщение получено из очереди {queue_name}, order_id={order_id}

Другие уровни логирования:
- WARN некритичные сбои (например, повторная отправка в очередь)
- ERROR исключения, невозможность изменить статус, ошибки расчета
- DEBUG только в dev средах, для отладки логики
- FATAL полный отказ сервиса 

2. Мотивация
Без централизованного логирования невозможно:
- быстро находить причину зависшего заказа
- отличать сбой от просто долгого расчета 
- подтверждать получение сообщений в RabbitMQ

Метрики, которые улучшатся:
- Время реакции поддержки на жалобы (с 1 дня до 10ков мин)
- MTTR (Mean Time To Resolve) инцидентов
- Доля потерянных заказов стремится к 0
- Удовлетворенность API партнров 
- Количество ручных запросов к разработчикам 

3. Предлагаемое решение
OpenSearch + Filebeat + Kibana
Причина выбора - бесплатная лицензия, совместимость с ELK, хорошая поддержка в облаке

- Filebeat на каждом инстансе API и RabbitMQ для сбора логов
- OpenSearch хранение и индексация
- Kibana визуализация и поиск

4. политика безопасности
- В логи не попадают пароли, токены, email, ФИО, номера карт
- Все чувствительные поля заменяются на псевдонимы на уровне приложения
- Доступ к Kibana только через SSO с ролями (devops, бэкенд разработчики, поддержка)
- Нет доступа у фронтенда и внешних пользователей


5. Политика хранения
- Отдельный индекс на сервис: shop-api-YYYY.MM.DD, mes-api-YYYY.MM.DD и тд
- Хранение 30 дней для продакшна, 7 дней для dev/release
- Размер: 1–2 ГБ день на сервис (оценка по текущему RPS)
- Автоматическое удаление через ILM-политику в OpenSearch

6. Анализ и алертинг
Алерты в Kibana на
- ERROR FATAL логи
- Отсутствие логов создания заказа > 10 мин 
- Резкий рост INFO: заказ создан (>1000/мин) подозрение на DDoS или баг
- Алерты >>>> Slack + автоматический тикет в Jira
